# 个人表达与版式偏好

以下来自用户明确提出的要求，作为默认值应用；新指令与本轮模板优先。数字、模板路径和研究术语的特殊约定应在当前项目记录，不扩展成所有PPT的固定内容

## 文案和术语

- 中文母语者自然表达，通俗易懂、适合口头汇报，保持专业性，不堆比喻，不用泛泛口号
- 每页标题和主要小标题用简短概括性短语，承担内容总结作用，不用长句讲完整结论
- 示例：“合并多份来源，保留预测时点已知的信息”改为“来源融合与可用时间”或“合并来源并提取信息”；根据页内实际内容选择，不机械套词
- 重要模型首次出现说明含义，包括工作名称的完整名称或中文解释、各部分代表什么；项目自定义名称说明是工作模型名，不写成公认标准模型
- 新缩写首次写全称或准确中文含义，再使用简称；本次用户明确允许直接使用DRT、OD、POI、ACO、PPO、LLM（大模型）、GIS
- 不把任意技术细节改成模糊白话：例如可以在“循环神经网络”后用备注保留GRU原名；若正文需区分具体结构，说明正式名称及作用
- 不使用“小时桶”“门控”“第0槽”等需要老师猜测的词；根据含义改成“逐小时预测时段”“事件影响权重”“保留原有服务安排”等，并核对没有改变计算机制
- 避免“实现闭环、深度赋能、系统性提升”等没有相邻证据的词；使用Nature润色与禁止防御性写作技能时保留真实限制和证据强度

## 字体、行距与标点

| 对象 | 默认设置 | 保护要求 |
|---|---|---|
| 普通文字 | 默认微软雅黑，用户要求时显式统一标题、正文与导航 | 先读主题映射；“微软雅黑（标题）”是主题表现，不必当作独立字体文件；公式例外 |
| PowerPoint公式 | 原生Office Math；默认数学字体，通常Cambria Math | 不统一改成微软雅黑，不转成图片或普通文本冒充公式 |
| 正文段落 | 版面允许时1.5倍行距 | 已手动调整的设置优先；先精简内容和调整布局，再考虑局部降低行距或字号 |
| 底部总结或提示框 | **加粗、单倍行距、水平居中、垂直居中** | 最新补充要求，覆盖正文1.5倍行距默认值；用户已经调整好的内容不要重置 |
| 标点 | 通常不加句号；多行并列用分号；完整单句末尾不加句号 | JSON、网址、小数点、文件名、引文和公式符号按自身语法保留 |
| 分点 | PowerPoint原生项目符号 | 不用输入字符“•”模拟列表；不对流程标题、JSON或公式强加项目符号 |

正文规则适用于正文文本，不把每个换行都当作并列分点：模型全称、标签和表头自然排版，避免全局替换后出现多余分号

## 配色与构图

- 默认蓝色系，以本轮模板的背景、主色、字体、导航和留白为设计依据
- 指定模板的金蓝等配色优先，中文化其导航；共用标题栏／栏目高亮优先在母版或布局层维护，页内研究内容保持可编辑
- 封面默认将研究题目作为中心视觉，按用户要求居中；已知姓名时使用准确的“汇报人：姓名”，不凭旧材料猜姓名或身份
- 喜欢圆角矩形框、小图标，以及不同颜色、字号和粗细文字组合突出重点；框内应有清楚的标题和内容层次
- 重点加粗区分标题、关键字段与普通解释，不把所有正文都加粗；底部框按上表单独处理
- 底部框总结本页核心思想或提供演讲提示：例如“先学习日常出行规律，再按事件条件修正预测”；不放内部实现备注、泛泛提醒或无关细节
- 图和公式必须与说明靠近；两条公式分成两个步骤或区域，写清“算什么、变量是什么、算完做什么”
- 流程编号只对应一个层级；同页上半部用①②③，下半部可用A／B，避免两组相同①②造成歧义
- 无实际解释价值的实现数字不占正文：例如“8个方案”若只是控制计算量，应移至备讲并说明目的
- 不为压页数牺牲可理解性；不靠不断缩小文字把复杂算法塞进同一页
- 用户移动正文与备讲的位置后，以最新顺序为准；隐藏页仍需正常排版和验证

## 方法步骤与内容属性标签

长方法跨多页展开时，默认在标题右侧使用模板主色的可编辑圆角矩形、白色加粗文字标明当前步骤；蓝色模板使用相应蓝色，不把RA色值套到其他模板。步骤名对应整体框架。总览、共同状态、共同评价及实验页按实际职责命名，不硬归入某个计算步骤。

用户需要区分研究工作归属时，可另设“核心扩展、任务建模、模型扩展、执行扩展、分析设计”等属性标签。步骤回答“当前讲到哪里”，属性回答“这一页承担哪类工作”；标签不代替具体技术说明，也不把所有页面标为创新。归属判断见[技术表达](technical-content.md#继承与研究工作归属)。

灰色副标题优先解释本页功能；直接借鉴指定基础模型的页面写明具体继承内容，其他页面保留原功能说明，成熟工具由必要引用交代。新增标签时调整标题宽度并检查长标题、引文及副标题间距，不以大幅缩字容纳标签；模板空间不足时按用户需求简化标签呈现。

## 框、文字与留白共同设计

- 方框大小由内容与页面角色决定。背景和研究缺口需要足够分点、条件与已有工作帮助理解；不要用巨大空白卡片承载一两句话，也不以缩小字号塞满所有细节
- 标题和正文看作一个文字块，块的上下都留边距，左右有稳定内边距；多框之间留明确间隙。少一行文字时可以视觉居中，不让标题贴上边、正文挤下边
- “呼吸感”来自卡片间距、文本内边距与有意义的留白同时调整。先适配文字与行距，再定框高；不要只把框拉大而保留旧坐标。案例里的22／30像素只作历史效果，不是统一尺寸
- 同一页各框对齐、间距有节奏；图标紧邻相应标题，编号与引文分开；流程箭头有方向且不碰字
- 英文词、中文标点、上下标和长网址避免不自然断行；原生公式与符号说明保持可读，不能为加引文破坏排版

## 图标

- 首选 https://www.iconfont.cn/ ，同套或相近线性风格，按当前模板确定统一主色；给用户明确十六进制色值，不只说“蓝色”
- 用户自行登录；不记录账号、密码、Cookie或登录态；用户已登录时直接继续，不重复要求登录
- 优先当前可用的内置浏览器或用户指定浏览器；使用前确认可控制性，不预设Edge或某个扩展一定能下载
- 下载后验证文件确实存在、SVG可解析、非空且可用；不能把点击下载等同下载成功
- 普通下载失败时先确认实际失败环节，避免一再换浏览器盲试；若当前浏览器API明确支持并已显示原始SVG，可从该图标的内联SVG读取，记录为提取，不能说下载按钮已修好
- `pageAssets.inlineSvgs`只在当前工具实际提供时使用，不臆造接口；不绕过权限或把页面截图当成原始矢量
- 需要图标时先列“用途／图标名称与搜索关键词／风格／确切颜色／格式／建议数量”清单。用户选择自己下载时，先约定素材目录，继续可独立完成的文案和排版，收到素材后再嵌入，不让整项任务等待图标
- 名称由本轮模块决定，例如活动日历、车队、延迟时钟、文档检索、定位、数据库、模型、分支、计算、刷新、校验清单和费用；这些是可选例子，不固定每次12个
- 优先SVG透明底；用户提供透明PNG时检查尺寸、清晰度、颜色与透明通道，当前显示尺寸够清晰即可使用，不为格式重新索要。保持宽高比与视觉尺寸一致，避免拉伸
- 文件名、原始页面地址、作者／图标库及可见授权信息随素材清单保留；原生矢量优先，实际PowerPoint兼容性要验证
- 最终核对实际嵌入与页面使用，不能把文件夹有12个等同已使用12个；没用到的图标如实说明，不为凑数装饰页面

## 修订保护

- 不把用户的正常改动当作版本损坏；从文件时间、内容和必要的当前会话确认工作对象
- 修改前备份、记录SHA-256；尽量按页／对象局部编辑，避免从早期生成脚本整套覆盖
- 用户说“这个我已经改好了，不用改”时，只记录新规则或保留现状，不再修改PPT
- 用户明确要求删除的旧页眉或副标题要全局核对，不影响仍需保留的封面题目；历史具体文案在当前项目核对，不把旧项目删词列表机械套到新PPT
