# 制作、版本保护与交付验证

## 读模板与保留用户版本

1. 枚举相关PPT的大小、修改时间、封面、正文、隐藏页和备注；以用户最新保存的正确版本为基础，不仅凭文件名的v1／v2判断
2. 抽读模板与参考页，记录画布比例、主色、主题字体、实际字号、对齐、留白、图标与导航；组织方法和视觉参考可以分别来自不同文件
3. 修改前保存原样备份和SHA-256。后续每轮用修改时间、哈希和实际内容核对是否有用户新改动；存在无法消除的版本歧义时再询问，不复用过期内存副本
4. 源文件与输出文件分开；用户说“已经改好”时保留其设置，不能用旧生成脚本把整套PPT重新覆盖
5. 用户指定文件夹就写入该文件夹，文件名清楚说明版本；不要用“22页正文”命名已经变为24页的文件

用户指定字母递增时沿用该规则，分别核对PPT与讲稿的最新版本，不假设两者字母相同。归档前再次核对源文件哈希与用户新修改；旧版被Office占用时，可复制备份并保留原位，核对副本一致后如实报告，不能声称已移动或强行关闭用户文档。没有用户要求时，不把此归档目录或命名方式套到所有项目。

## 工具选择与可编辑性

优先遵守当前可用PPT技能的工具与模板路线。继承已有PPT时选原生编辑或工具支持的保真往返；普通小改不需要整套重构。当前技能版本路径从实际清单发现，不固定某个插件版本

如果使用Office COM或OOXML做局部修改，先验证工具和解析库，保护母版、布局、图片、链接、备注、隐藏状态与兼容对象。不把整页截图当作可编辑成品，也不把公式改成图片

- ZIP部件顺序不能当作幻灯片顺序，读取`presentation.xml`及其关系映射
- 增删页时维护幻灯片ID、关系、内容类型、备注与备注关系；复用布局和主题，不仅复制`slideNN.xml`
- 原生Office Math可能位于`AlternateContent`的Choice／Fallback分支，避免重复计数、重复显示或误删兼容对象
- 区分主题字体引用与显式字体，普通文字改字体时跳过公式；公式字体和公式结构分别验证
- 文案替换按段落和run处理，避免破坏加粗、颜色、项目符号和公式；全局清句号不得破坏JSON和文件名
- 正文按1.5倍行距设置时，底部框单独设置为**加粗、单倍行距、水平和垂直居中**；比例行距写入对应的比例值，不把1.5误作固定1.5磅
- 检查文本内边距与真实上下居中，不能只对文字设水平居中；底部矩形和独立文字框都应对齐
- 共用标题栏和栏目高亮优先改母版／布局，保持各章一致；用户只要求留白、居中或补模型名称时，从最新成品局部改，不重跑旧内容生成器覆盖其手调
- 图形与文字分组后，核对组坐标、子坐标及边界一致；扩大文本框或加引文后重新看实际画面，避免缩放错位、覆盖步骤数字或标题
- 修改幻灯片关系与内容类型时，检查关系ID及部件声明唯一，克隆备注保持一页一份。引用页增删后清理重复声明并按演示顺序验收，ZIP可读不等于PowerPoint可打开
- 原生公式需适配当前编辑工具；导入器无法重构的公式保留原生对象并在PowerPoint核验，不因工具警告擅自转图或删减

## 图表与算法页

流程图使用用户要求的可编辑对象，保留方向、层级和分组。模板允许圆角框时使用，但不要每个短词都包一层框

算法页优先展示“输入—计算—输出—作用”，并在显眼位置写清模型框架与求解形式。基础关键公式及其解释进入正文，完整推导或次要约束按价值移入备讲；不能借“复杂”把整个核心模型藏起来。只显示参数数字而不说明意义时，应删减或转备讲

表格行高与正文行距一起核对：长单元格换行后容易碰到边框，先精简或调整列宽，不一味缩字。新增来源页也需要渲染，不能因隐藏就免检

正文引文、APA书目和讲稿的检查见[必要引用](citations.md)与[叙事与内容取舍](narrative-and-priorities.md)。文末按需要分几页，不加排序规则等制作解释；引文精简后重新核对连续编号、实际被引条目、页码和讲稿索引。

## 实际PowerPoint验证

Windows上可用PowerPoint时，打开独立候选副本，导出各页图像和适合的正文PDF，必要时另存核验副本。使用规范的Windows绝对路径；斜杠形式文件路径可能在COM调用中报找不到路径

用户可能已经开着其他演示文稿；只关闭本次打开的文档，不无条件退出整个PowerPoint进程。导出与另存可能规范化PPTX并改变字节，不能认为“只导出PDF”必然不会改写正在验证的副本

遇到文件被占用，先识别具体占用演示文稿与未保存状态；优先使用候选副本或新输出名。不能为释放锁一律将`Saved=true`后关闭，避免丢掉用户手动修改。旧脚本默认复制自旧输出时，先重新核对输入文件、页序与形状标识。

发布前冻结最终文件：

1. 完成原生打开、另存、渲染及必要修复
2. 对最终实际字节重新检查结构、文字、公式、隐藏页和SHA-256
3. 将最终核验结果与交付文件的SHA-256对应；不要拿规范化前的校验记录冒充最终记录
4. 若发布工具禁止覆盖，使用新的临时目标和新的回执路径；已存在的回执也可能导致发布失败，失败后检查实际文件是否存在，不盲目重试
5. 后续验证尽量只读；必要时读副本，避免再次改变已经冻结的交付文件

工具不可用时明确已做结构检查、尚未完成原生打开或视觉验证；不要将包结构通过解释为版面通过

## 检查清单

| 范围 | 核对点 |
|---|---|
| 事实 | 设计、实现、运行、结果不混淆；数字与来源相符；演示算例标识清楚 |
| 研究主线 | 核心问题、基础模型、改进位置、预测到行动接口与验证闭合；主要方法不只放备讲 |
| 受众 | 屏幕为老师解释研究；对用户的改稿说明、排序规则、工具与验收记录未混入正文 |
| 页序 | 正文／隐藏页数量与用户决定一致；正文里的提示词页未被放回备讲 |
| 文字 | 短语标题、自然中文、缩写定义、无生造术语；不保留要求删除的旧页眉 |
| 底部框 | 本页总结或演讲提示；加粗、单倍行距、水平和垂直居中 |
| 公式 | 原生可编辑、默认数学字体、变量和整体含义、单位／条件及下游用途完整，无重复兼容副本 |
| 版面 | 无截断、遮挡、空洞大框、拥挤或不自然断词；框内上下留空、框间有间距，封面与底部按用户要求对齐 |
| 图标 | 名称、颜色与页面含义一致；比例、透明度和清晰度正常；实际使用与文件清单一致 |
| 引用 | 必要算法／公式及直接资料旁编号准确，未机械给所有术语加引文；文末APA条目无遗漏、无闲置和排序解释句 |
| 来源 | 内部正文与备讲依据可追溯，屏幕未恢复已删除“来源”行；备讲编号和图号有效 |
| 讲稿 | 页码、标题、正文／备讲、引用与备注同步；口播有真实承接，计划时长与实测时长区分 |
| 实质对应 | 主讲核心模型、计算和主张在屏幕上有入口；详细解释保留，步骤顺序与框架一致；只改讲稿时准确说明备注是否同步 |
| 标注 | 步骤标签对应框架，属性标签不冒充效果结论；直接继承说明与实际模型相符，灰字未变成逐页归属清单 |
| 数据与符号 | 元信息与项目样本范围分开；训练、验证、评测日期一致；公式与解释中的符号、时间范围、单位相互对应 |
| 文件 | PPT成功打开，输出路径正确，预览与对应版本一致；用户原文件未被覆盖 |

随附检查器只辅助文字、页序和显式格式核对；逐页缩略总览后，重点打开密集页、公式页和来源页查看，不能只看缩略图就宣布全稿无问题

联合修改PPT和讲稿时，逐页核对主要内容与对应备注，不能只比较标题列表。用户只要求压缩讲稿或粘贴替换文本时，保持授权范围，并明确PPT和备注是否改动；后续要求同步时，再以最新文件合并这些修改。结构检查器不验证语义、贡献归属、公式推导或可理解性，不把脚本读取成功当作这些项目通过。

## 交付与归档

交付可编辑PPT、适当的PDF及简短变更说明；按请求提供逐页讲稿，并同步备注。PDF明确包含正文、参考文献还是隐藏备讲；总页数分别报正文、隐藏备讲和参考页，避免把书目页算成主讲页。数据来源、素材和验证明细保留为相邻记录，不放进面向老师的正文

遵守项目提交约定，精确暂存本次文件，不把用户修改的原版或仓库其他脏文件一并提交。只汇报实际完成的验证，不为每轮PPT都强制增加无必要产物
